# Evaluation and leakage controls

Supervised samples are ordered by **distinct prediction date**. The older 60% of dates form fitting, the next 20% validation, and the newest 20% test. Equal dates stay together. If an earlier sample's target interval would cross a partition boundary, it is purged from that earlier partition. At least ten distinct dates and five retained rows per partition are required. The model is selected using validation only, refitted on retained train plus validation, then evaluated on the held-out test period. There is no random time-series split or test-based model selection.

Every feature source date must be earlier than its prediction date. Injury outcomes on D through D+6 are labels, not features; the negative class requires seven confirmed daily observations. Health uses its own event log with the same confirmed-follow-up rule. Performance uses the actual rating of a match whose own statistics are excluded from its feature snapshot. Pipeline imputation, scaling and position encoding are fitted only within each candidate's fitting partition.

Classification reports accuracy, precision, recall, F1, ROC-AUC when both test classes exist, and a fixed 2×2 confusion matrix. Injury and Health candidate selection uses `0.7 × validation recall + 0.3 × validation F1`. Performance reports MAE, RMSE and R² when the test targets vary; candidate selection uses lowest validation MAE. Accuracy or R² alone do not establish usefulness. Reviewing many experiments against the same test period can still overfit human decisions to it.

The demo outcome calendars are authored fictional scenarios with positive and explicit negative days. Measurements have plausible shared patterns and unrelated fluctuations; outcomes are not perfectly determined by one input. This makes a useful pipeline demonstration, not a benchmark for real athletes. Windows around the same event overlap, players recur across partitions, and measured outcomes can be incomplete or biased. The reported test scores estimate later records from this fictional roster, not new-player or clinical generalization. Classifier probabilities and display bands are uncalibrated.

This cleanup intentionally does **not** train any model or report new metrics. After manual import and training, inspect the actual validation and test results shown by Model Analysis and Health Monitoring.
